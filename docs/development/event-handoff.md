# 鸣潮活动自动化交接

记录日期为 2026-11-20。本页随 `feat/glory-hill` 分支更新，包含荣耀之丘和拉海洛方块两项任务。

## 换电脑运行

```powershell
git clone --branch feat/glory-hill https://github.com/xiaxianyue233/ok-wuthering-waves.git
cd ok-wuthering-waves
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -B run_test.py tests/TestGloryHill.py tests/TestRahaiBlocks.py tests/TestConfig.py tests/test_generate_release_notes.py
.\.venv\Scripts\python.exe -X utf8 main_debug.py
```

使用 Windows 原生 PC 客户端，游戏语言设为简体中文，窗口保持 16:9。出牌、点按和拖放阶段保持游戏在前台。项目源码中的 `config.py` 已登记两项任务。开发模式会使用当前仓库代码。已安装的 OK-WW 使用独立目录，新 PC 继续调试时从仓库启动。策略模块改动后重启开发进程。

实测时可直接使用「日常活动」下的任务。使用 MCP 时，按仓库的 [OK-Script 开发说明](../../.agents/skills/ok-script-develop/SKILL.md) 启动和连接实例，选定本仓库运行时，把 `tools/event_repro/` 里的脚本路径传给 `run_task`。本机日志保存到运行时的 `logs/mcp/<run_id>/run.log`。原始日志、个人配置与连接凭据由本机保管。

## 荣耀之丘

- 从已打开的 NPC「选择挑战」界面启动时，任务识别对手并选择已配置的卡组和决斗家，然后处理起手、部署、战斗及结算。也能从相应的对局中间状态启动。预先在游戏中保存同名卡组。
- 布兰特用「双镰坚守 / 坎特蕾拉 / 适者生存」，夏空配置为「冰火调谐 / 珂莱塔」，露帕配置为「双镰坚守 / 坎特蕾拉」。套牌列表见[中文功能说明](../zh-CN/index.md#荣耀之丘自动对战实验)。布兰特备战页显示初始生命 55，战斗阶段每回合所受伤害减 6。
- 实机已确认战斗 2×，同回合曾测得连续出牌间隔约 5–7 秒。跨回合手牌缓存要求画面、费用和伤害都相符，且匹配唯一。新牌及场上技能仍重新读取。缓存的单独提速尚未量化。
- 后台采集探针和后台操作是两件事。自动出牌所需的拖放当前依赖前台，失去焦点会等待。遇到手牌或棋盘无法确认时保留现场。
- 《荣耀之丘：激斗重燃》能识别并安全停止。领域、奇藏和费用规则待适配，现有自动出牌策略尚未覆盖该活动。

最新策略在已有第一只车刃镰、手里没有第二只且能组成前排嘲讽与抽牌时，优先在前排使用咕咕河豚接巡徊猎手或先锋幼岩，再继续铺后排。这条策略有回归测试，仍待实机。已实现能量不足时逐次重构备用牌并重读棋盘，单回合 `1→2→3→调谐` 整条链路仍待实机触发。手牌折叠时的核心召唤已由单步探针确认，自动展开重试仍待实机触发。

下一局从布兰特「选择挑战」页启动，记录前排嘲讽是否形成、第二只车刃镰是否上场，以及最后的游戏结算文字。MCP 脚本执行成功仅表明任务走到结算，胜负以游戏显示为准。

## 拉海洛方块棋盘续跑

有两种入口。关卡列表会扫描已解锁且未通关的难度。已打开的积分或奖章棋盘会只继续当前关卡，开始前关闭教程和遮挡。首次通关从棋盘入口启动时会保留「获得」奖励页。重玩从最后一次得分落块后的验证开始采样「挑战成功」，识别到后正常结束，随游戏返回列表。单独出现满分数字或返回列表不足以判定通关。

上游 v3.8.6 已包含奖章棋盘截图和托盘回归。续跑修复基于该版本，沿用其灰块识别和消除实现。之前本机已实测奖章棋盘续跑和首通奖励页。上游实测确认了旧代码在「回转的深空」达到 `4500/4500`、出现「挑战成功」并直接回到列表时误报失败。修复后的转场已通过自动化回归，仍待相同关卡实机复测。验证范围是当时已开放的关卡，新开放关卡需继续复测。

1. 打开已经通关的「回转的深空」4500 分棋盘。启动「3.8 拉海洛方块·逆转」，确认重玩达标后正常退出，游戏回到关卡列表。本仓库的 `rahai_replay.py` 可用来验证该入口。
2. 打开一个尚未通关的奖章棋盘并启动。确认首次达标后停在「获得」。从关卡列表启动时，应领取奖励并继续扫描。
3. 退出关卡或输掉重玩时，确认任务仍报未确认通关。回看日志并记录分数、游戏结算文字、运行编号和截图。

独立续跑分支为 fork 中的 `fix/rahai-board-resume`，可单独审查拉海洛改动。上游评审见 [#1865](https://github.com/ok-oldking/ok-wuthering-waves/pull/1865)，已合入的奖章托盘测试见 [#1866](https://github.com/ok-oldking/ok-wuthering-waves/pull/1866)。
